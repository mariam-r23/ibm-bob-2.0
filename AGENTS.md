# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Project

MonoSplitter AI — visualizes a monolith's code + DB coupling as an interactive graph, then uses Bob to carve a module into a standalone microservice. IBM Bob 2.0 hackathon project. Phase 1 (graph) is complete; Phase 2 (carve-out engine) is in progress.

## Services & Ports

Three separate npm projects, each with its own `node_modules/`. Install and run from each directory independently — there is no root `package.json`.

| Service | Dir | Port | Start |
|---|---|---|---|
| monolith | `monolith/` | 4000 | `cd monolith && npm start` |
| graph-service | `graph-service/` | 4100 | `cd graph-service && npm start` |
| frontend | `frontend/` | 5173 | `cd frontend && npm run dev` |
| payments (carved-out) | `extracted-services/payments/` | 4200 | written by carve-out task |

`madge` must be installed globally: `npm install -g madge`

## No Tests Yet

`tests/` is an empty scaffold. The contract test (`tests/payments-contract.test.js`) is **generated by Bob's carve-out task** — run with `node tests/payments-contract.test.js`. There are no linters or formatters configured.

## Carve-Out Task

The Bob carve-out is triggered by pasting `bob-tasks/carve-out-payments-prompt.md` into Bob IDE in **Agent mode**. Bob writes status to `bob-tasks/carve-out-status.json` (shape: `contracts.md §4`). The skill driving this lives in `.bob/skills/carve-out-microservice/SKILL.md`.

Scope is strictly ring-fenced: Bob should only touch `extracted-services/payments/`, `monolith/users/`, `bob-tasks/`, `tests/`, and `docker-compose.yml`.

## Critical Architecture Rules

- **`docs/contracts.md` is the single source of truth** for every JSON shape shared between frontend/backend/Bob output. Any shape change requires a `[CONTRACT]`-prefixed commit and must notify the other teammate before pushing.
- The two coupling points are **deliberate** and must remain intact until the carve-out task rewrites them:
  1. `monolith/users/index.js` directly `require()`s `../payments` and calls `processPayment()` in-process (coupling #1).
  2. Both `users/` and `payments/` share `monolith/db.js` — the single in-memory data store (coupling #2, no real DB).
- `graph-service` uses `madge` **as a library** (not CLI shell-out), and collapses file-level deps into module-level nodes. `moduleForFile()` splits on `/[\\/]/` (not `path.sep`) because madge always returns forward slashes on all platforms.
- The graph endpoint returns an additive `meta.filesScanned` and per-node `files[]` array beyond the `contracts.md §1` minimum — these are real madge values, not invented.
- Frontend merges code graph (`/api/graph`) and schema graph (`/api/schema`) **client-side** in `graphTransform.js`. The Vite dev server proxies `/api/*` to `localhost:4100` — frontend code uses only relative `/api/` paths, never hardcoded ports.
- `graph-service/schema.json` is the Tier 1 DB schema — hand-authored static file, not generated from a live DB.

## Code Style

- CommonJS (`require`/`module.exports`) throughout the backend. Frontend uses ES modules with `.jsx`/`.js` extensions.
- Error objects thrown from business logic carry a `.status` property (HTTP status code); route handlers use `err.status || 500`.
- `payments/index.js` exports both `{ router, processPayment, listPaymentsForUser }` — the router is mounted in `server.js` as `require('./payments').router`.
- No TypeScript; no linter configs present.

## Branching

`main` → always demoable. Personal branches: `yourname/module-name`. Merge into `phase-N-integration` first, never directly into `main`.
